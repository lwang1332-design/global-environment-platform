# 三级离线地图架构

## 1. 目标

平台地图采用“在线双源 + 本地三级离线”的组合架构：

1. 全球低精度：保证任何国家/海域断网时均可定位；
2. 中国中精度：覆盖国内项目选址、区域环境评估和省市级定位；
3. 项目区域高精度：仅围绕实际项目点配置高缩放级别瓦片，控制磁盘占用。

坐标体系统一使用 EPSG:3857，瓦片规范统一为 XYZ / 256×256 px / PNG。

## 2. 精度分层

| 层级 | 缩放级别 | 覆盖范围 | 默认目录 | 主要用途 |
| --- | --- | --- | --- | --- |
| 全球低精度 | Z2–Z5 | 全球 | `tiles/global/{z}/{x}/{y}.png` | 全球定位、国家/区域判断 |
| 中国中精度 | Z6–Z9 | 73–135°E，18–54°N | `tiles/china/{z}/{x}/{y}.png` | 国内省市、海域、项目区域判断 |
| 项目高精度 | Z10–Z13 | 单项目约100 km半径，可配置 | `tiles/projects/{projectId}/{z}/{x}/{y}.png` | 场址、海岸、道路及项目周边定位 |

## 3. 自动切换规则

### 在线

- 中国普通区域：天地图优先（已配置 Key）→ 对应本地离线层 → OSM；
- 海外区域：对应本地离线层 → OSM；
- 项目高精度区域：项目高精度本地层优先 → 天地图（中国项目）→ OSM。

### 断网

- 只使用本地瓦片；
- 系统自动限制最大缩放级别：全球最多 Z5，中国最多 Z9，已安装项目包最多 Z13；
- 不允许继续放大到不存在的数据层，从源头避免白屏。

## 4. 数据量控制建议

瓦片数量取决于覆盖范围和实际压缩率。按常见静态 PNG 估算：

- 全球 Z2–Z5：约 1,360 张瓦片，建议控制在约 40–100 MB；
- 中国 Z6–Z9：约 8,000 张瓦片，建议控制在约 250–600 MB；
- 单项目约 200×200 km，Z10–Z13：通常约 4,000 张量级，建议约 100–300 MB/项目。

因此基础离线包建议控制在 0.3–0.7 GB；项目高精度包按项目独立安装，不进入公共 GitHub 仓库。

## 5. 项目高精度包配置

在 `tiles/manifest.json` 的 `projects` 中增加项目条目。例如：

```json
{
  "id": "project-a",
  "name": "项目A",
  "enabled": true,
  "bbox": [118.8, 29.0, 121.2, 31.0],
  "minZoom": 10,
  "maxZoom": 13,
  "template": "./tiles/projects/project-a/{z}/{x}/{y}.png"
}
```

`bbox` 顺序固定为 `[west, south, east, north]`。

## 6. 数据生成原则

- GitHub 仓库只保存地图引擎、清单和少量示例，不直接提交数百 MB～GB 的离线瓦片；
- 本地 Windows 部署目录中单独放置 `tiles` 数据包；
- 离线瓦片应来自允许离线使用/自建切片的数据源；不要对公共 OSM 标准瓦片服务进行大规模批量抓取；
- 推荐后续基于 OpenStreetMap 开源数据 + 自建切片流程生成项目包，或由企业内网地图服务导出 XYZ 包。

## 7. 后续增强

下一阶段可增加：

- “项目地图包管理”页面：导入/删除/校验项目包；
- 地图包完整性检查和容量统计；
- 根据项目经纬度自动生成 50/100/200 km 三档项目包范围；
- PMTiles/MBTiles 单文件方案，用于减少几十万小文件；
- 本地地图版本号、数据日期和许可信息展示。
