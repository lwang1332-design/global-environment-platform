# V2.9 部署、验收与故障排查

## 1. 架构

```text
GitHub Pages / PWA
      |
      | GET 最新正式参数 / POST 管理员发布
      v
Vercel Serverless API
      |
      | Service Role，仅服务器持有
      v
Supabase PostgreSQL
```

前端永远不保存 `SUPABASE_SERVICE_ROLE_KEY`、数据库密码、GitHub PAT 或 Vercel Token。

## 2. Supabase 数据库部署

在 Supabase SQL Editor：

1. 执行 `supabase/schema.sql`。
2. 确认 `config_versions` 表、`config_version_seq` 序列、`publish_config` RPC 已创建。
3. 首次部署且数据库为空时执行一次 `supabase/seed.sql`。
4. 检查：

```sql
select version,updated_at,updated_by,description,is_active
from public.config_versions
order by updated_at desc;
```

首次应看到 `V2.9-P001` 且 `is_active=true`。

## 3. Vercel Serverless 部署

在 Vercel 中导入 GitHub 仓库 `lwang1332-design/global-environment-platform`。本项目 `/api` 目录即 Serverless Functions，无需把 GitHub Pages 迁移到 Vercel。

生产环境变量：

```text
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<仅服务器保存>
ADMIN_PASSWORD_HASH=scrypt:<salt>:<hash>
ADMIN_SESSION_SECRET=<至少32字节随机字符串>
ALLOWED_ORIGIN=https://lwang1332-design.github.io
ADMIN_TOKEN_TTL_SECONDS=3600
```

生成管理员密码哈希：

```bash
node scripts/hash-admin-password.mjs "新的管理员密码"
```

生成随机会话密钥示例：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

部署后依次检查：

```text
GET  https://<your-vercel-domain>/api/health
GET  https://<your-vercel-domain>/api/config/latest
GET  https://<your-vercel-domain>/api/config/history
POST https://<your-vercel-domain>/api/auth/login
```

## 4. GitHub Pages 接入中央 API

编辑 `assets/v29-runtime-config.js`：

```js
window.V29_RUNTIME_CONFIG={
  configApiBase:'https://<your-vercel-domain>/api'
};
```

这里只允许出现公开 API 地址，不允许出现任何 Secret。

## 5. 参数发布流程

```text
管理员登录
  ↓ 服务端验证
修改参数
  ↓
应用并重算（仅当前浏览器）
  ↓
检查模型结果
  ↓
输入发布说明
  ↓
发布正式参数（全网同步）
  ↓ 服务端再次校验参数合法性
Supabase 原子生成 V2.9-Pxxx
  ↓
其他用户打开页面/点击评估
  ↓
GET latest → 更新本地最近有效快照 → 使用新参数计算
```

导入 JSON 只进入本机调试状态，不会自动发布。

## 6. 参数三级容错

```text
云端最新正式参数
  ↓失败
LocalStorage 最近有效正式参数
  ↓仍不存在
V2.8 继承的程序默认参数
```

页面会显示参数版本与来源。云端读取成功后会立即覆盖本地正式快照；本机调试参数不会覆盖正式快照。

## 7. 最近项目数据离线机制

V2.9 使用 IndexedDB `GE_V29_ENGINEERING` 保存最近一次项目的小时级环境数据。原因是 3～5 年 ERA5 小时数组可能超过 LocalStorage 的常见容量限制。

实时 ERA5 获取成功并完成计算后自动写入快照。离线或同一项目实时数据源失败时，可恢复最近快照并用当前有效参数重新计算。

## 8. 风温联合公式

逐小时按照相同数组索引和相同 ERA5 时间戳配对：

```text
Ti = temperature_2m[i]
Vi = wind_speed_10m[i]
```

若未来接口改为 `u10/v10`，V2.9 模块保留：

```text
Vi = sqrt(u10[i]^2 + v10[i]^2)
```

仅当 Ti 与 Vi 同时为有效有限值时计入 `Hvalid`。

```text
Ii = 1  条件同时满足
Ii = 0  其他
Hjoint = ΣIi × 1h
Pjoint = Hjoint / Hvalid × 100%
```

多年年均：

```text
Hjoint,annual = Hjoint / 统计时间跨度(year)
```

二维分布：

```text
温度 bin = 2℃
风速 bin = 1m/s
Pij = Nij / Nvalid × 100%
```

## 9. 验收场景

### A. 跨电脑同步

1. A 电脑管理员把 `capHigh` 从 45 改为 50。
2. 先“应用并重算”，确认当前 A 使用 50。
3. B 电脑仍应保持当前正式参数。
4. A 点击“发布正式参数（全网同步）”。
5. Supabase 新增一行并生成下一版本。
6. B 刷新或点击评估，参数来源显示“云端”，`capHigh=50`。

### B. 离线参数

1. B 成功读取一个正式版本。
2. 断网后刷新已安装 PWA。
3. 参数来源应显示“本地缓存参数”，版本不变。

### C. 调试不发布

管理员本机把 45 改为 55，仅点击“应用并重算”。当前页面使用 55，但 Supabase active 版本不变。只有点击“发布正式参数（全网同步）”后其他用户才获得 55。

### D. 风温联合

输入 `T≥35℃`、`V≤3m/s`：

- 显示 `h/y`；
- 显示共同有效样本 `Hvalid`；
- 显示百分比 `Pjoint`；
- Heatmap 画出 35℃ 水平阈值、3m/s 垂直阈值和高温低风区域；
- 手工用小时数组重新计数应与页面完全一致。

## 10. 故障排查

### 页面显示“中央参数 API 尚未配置”

检查 `assets/v29-runtime-config.js` 是否填写 Vercel `/api` 地址。

### `GET /api/config/latest` 返回 503

检查 Vercel 的 `SUPABASE_URL` 与 `SUPABASE_SERVICE_ROLE_KEY`。确认 Supabase `config_versions` 已创建。

### 登录总是失败

确认 `ADMIN_PASSWORD_HASH` 是 `scripts/hash-admin-password.mjs` 生成的完整 `scrypt:<salt>:<hash>`；修改环境变量后需要重新部署。

### 发布返回 401

管理员会话过期。重新打开管理员页并进行服务端验证。

### 发布返回 422

服务端参数合法性校验失败。响应 `errors` 会指出具体参数。前端对应输入框也会标红。

### 发布返回 409

参数 `schemaVersion` 与服务端 V2.9 不兼容。不要直接发布旧版/未知结构 JSON。

### 页面显示“本地缓存参数”

中央 API 不可访问或网络离线。工程计算仍可继续；网络恢复后“读取最新参数”或下一次评估会重新同步。

### 风温联合分析数据不足

检查 ERA5 小时数据的 `temperature_2m` 与 `wind_speed_10m` 是否同时存在。联合统计不会用温度有效小时去替代缺失风速小时，也不会固定用 8760 做分母。

### Heatmap 无数据但其他模型有结果

在浏览器控制台检查 `V29Joint.calc()` 返回的 `reason` 与 `valid`。若旧 PWA 缓存未更新，强制刷新或重新安装 PWA。
